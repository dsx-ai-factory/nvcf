# Privileged tools outside the workload's filesystem

`pidns_capture.go`, `pidns_subtree.go`, `pidns_restore.go`, `restore_v2.go`, `tar_extract.go`,

## Rule

The agent runs as host root. A dynamically linked program reads its loader configuration and loads shared
libraries from the filesystem it runs in, and the workload controls its own filesystem; a read-only bundle
mount does not cover what the loader reads. So no privileged tool of the agent's runs from the workload's or the
placeholder's filesystem, except the GPU tool (below).

| What | How it stays outside | Code |
|---|---|---|
| CRIU dump | The agent's own CRIU dumps the container's whole pid namespace from outside it, with `--root` into the container and every mount CRIU cannot rebuild declared external. Dumping the whole namespace also makes every pid free at restore | `internal/agent/pidns_capture.go` `dumpPIDNamespace`, `pidNSMounts` |
| CRIU restore | The agent's own CRIU, entered only into the placeholder's pid and network namespaces (`nsenter -p -n`, then `pidns-restore-exec`). CRIU's TCP lock and unlock act on the network namespace it runs in, which must be the pod's. A checkpoint captured inside the container's namespaces is no longer restored; a new capture replaces it | `internal/agent/restore_v2.go` `restoreV2`; `cmd/agent/pidns_exec.go` `pidNSRestoreExec` |
| Replays (rootfs diff, replay mounts) | Extracted by the agent in Go, through a directory opened as an `os.Root` under the placeholder's root: no tar or mkdir runs in the placeholder, and no path resolves outside its root | `internal/agent/tar_extract.go` `extractTar`; `internal/agent/confined_fs.go` `openConfinedDir` |
| Namespace entry | The agent opens `/proc/<pid>/ns/*` once, checks the process is in the initial user namespace with no effective `CAP_SYS_ADMIN` at that moment, and has nsenter enter exactly those descriptors. Not guaranteed: the check reads only the effective set, so a process that keeps `CAP_SYS_ADMIN` in its permitted set could raise it later and change its mounts | `internal/agent/nsenter_fd.go` `nsenterByFD`; `internal/agent/bundle_tools.go` `hasCapability` |

## Pods that share one pid namespace

With `shareProcessNamespace` the pid namespace's init is the pause process, so a container cannot be dumped as
its own namespace. It is dumped as its own process tree (a subtree), still by the agent's CRIU: the agent enters
only the pod's pid and network namespaces, and `pidns-dump-exec` mounts a procfs of that pid namespace in a
private copy of the agent's mount namespace, where CRIU finds the tree by its pids. The checkpoint's marker
records the subtree and its root's pid (`pidns_subtree.go`).

The restore recreates the tree at its dumped pids in the placeholder's shared pid namespace: the placeholder
bumps `ns_last_pid` clear of them, and the restore waits until no placeholder task holds a pid the checkpoint
recreates.

## The placeholder's root

A bind mount cannot take its source from another mount namespace: `mount --bind /proc/<pid>/root`, and
`open_tree` with `OPEN_TREE_CLONE`, fail from outside with `EINVAL` (GB300 nodes, kernel 6.17). So the node
bundle's static agent binary, run in the placeholder's mount namespace, clones the mount tree there
(`placeholderFilesExec`) and passes it back over a socket pair; the restore helper attaches it with
`move_mount` at `agent.PIDNSRestoreRoot` for CRIU's `--root` (`pidns_restore.go` `pidNSRestoreFiles`).

## Not done

`nvsnap-gpu-suspend` still runs as root inside the workload's mount, pid, net, ipc and uts namespaces, entered
by descriptor (`gpushare.go` `gpushareToolEnv`), because it must load the workload's libcuda. Running it as the
workload's uid and gid, with only `CAP_SYS_PTRACE` effective and `no_new_privs`, would close the remaining
loader exposure; it needs the GPU tool owners to confirm the driver checkpoint API and the control socket's peer
check work that way. Until then the bundle mount at `/criu-bundle` stays for the GPU tool.
